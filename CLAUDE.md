# OVERBOOKED! — Survive the DevFest

Co-op game for people who run tech events, with GDG DNA: a project by Nicola
Guglielmi (GDE, GDG organizer), "sulla scia" of Last Mile Hero
(`../LastMileHero`, `../LastMileHeroFlutter`). Credits name the author only,
no chapter as co-author; chapter and city start empty (no default place). A season of six
events (meetup → Study Jam → Women Techmakers → I/O Extended → night hackathon
→ DevFest), each in three acts: the Countdown (turn-based organizer dilemmas,
each tip cites a source), the day (real-time co-op arcade on a deterministic
sim, with a staff chat and chaos events), the guided retro. Each event has
three goals (`ev.goals`, one star each, evaluated in `js/sim.js`); stars buy
the chapter's kit (`DF.PERKS`). A tutorial (`js/coach.js`) pauses the day the
first time something new happens. Five languages; witty, local copy; sources in
`DF.SOURCES` (`js/prep.js`) and `docs/RICERCA.md`.

Brand: OVERBOOKED! — event ticket + red rubber stamp (`.stamp` with the SVG
`#ink` filter), ticket yellow `#FFD23F`, stamp red `#E63B2E`, ticket paper
`#FFF7E1`, backstage `#0F1018`, GDG four colours as a lanyard; Bungee for
display, Google Sans Flex / Google Sans Code for text, Noto Color Emoji;
Murphy the gremlin is the mascot.

## Stack

Vanilla JS, classic `<script>` files sharing the global `DF` namespace (the
page opens from file:// and the pure modules load in Node). No dependencies.
Canvas2D renderer with sprites, Web Audio synth, DOM screens. Online rooms:
Firebase RTDB + anonymous auth or BroadcastChannel. `server/server.mjs` (Node,
no deps) serves the game and runs the Gemini tasks.

## Commands

```bash
node server/server.mjs 8765          # dev server + AI (GEMINI_API_KEY in .env)
node tools/check.mjs                 # MANDATORY before any publication
node tools/playtest.mjs 10 --e2e     # Countdown strategies -> day, per event
node tools/playtest.mjs 10 --event=devfest
node tools/build.mjs                 # dist/index.html (single file) + dist/artifact.html
node tools/translate.mjs [fr es de] [--only=cards,chat]
python3 tools/gen_sprites.py [names] [--ref] [--webp]
```

URL flags: `?day=solo|duo&event=meetup|studyjam|ioext|devfest`, `?dev`
(`__df.advance(sec, profile)`, `__df.tick(n)`, `__df.attract(sec)`), `?emu`.

## Conventions that matter

- **Pure modules stay pure**: `core`, `i18n`, `lang/*`, `content`, `venue`,
  `chat`, `sim`, `bot`, `prep` never touch the DOM and never use
  `Math.random` (seeded RNG only). The playtest and the online host depend on it.
- **Playtest gate before every publication**: changes to timers, spawns,
  penalties, cards, decks, goals, pace or loadout math are judged on
  `tools/check.mjs`, not by feel. Curve per event: meetup forgiving (≥ 3.4 even
  unprepared); Study Jam, Women Techmakers, I/O Extended, hackathon: skipping
  the Countdown ≤ 3.3, a good one ≥ 3.5 and worth ≥ +0.7; DevFest: skipping
  ≤ 2.5, novice with a good Countdown ≥ 4.0, never above 4.8.
- **New problem types need a coach text** (`coach.p.<type>` in the packs) and,
  if someone has to be walked somewhere, an entry in `DF.CRITTERS`.
- **Taps work by themselves**: tapping a problem sends `auto: true`, the
  organizer works on arrival without HOLD; keyboard players still hold.
- **Every user-facing string lives in `js/lang/*.js`** (`DF.t(key, vars)`).
  Write `it` and `en` by hand, then regenerate `fr/es/de` with
  `tools/translate.mjs --only=<top-level keys>`; the gate checks that all five
  packs have the same keys, array lengths and `{placeholders}`.
- **Runtime AI is an opt-in extra, off by default.** Two modes: the player's
  own key (kept in this browser only — sessionStorage, or localStorage if they
  tick "remember" — and sent only to generativelanguage.googleapis.com), or the
  host's key on `server/server.mjs`. The five tasks live once in
  `js/ai-tasks.js` (prompts, schemas, validation) and run in both. Only
  `js/ai.js` may touch the player's key (the gate checks it). Every task needs an
  offline fallback; the Artifact build has no AI at all. Untrusted cards go
  through `sanitizeCard`. Never print or commit `.env`, never type a real key
  into a page while testing (use Node, or a fake key for the UI).
- **Firebase Hosting serves `dist/web/`**: no inline scripts, ever — the CSP in
  the page is generated by `tools/build.mjs` from `firebase-config.js`.
- **No project config in git, ever.** `firebase-config.js`, `.firebaserc`,
  `functions/.env.*` and `CLAUDE.local.md` (project ids, sites, keys, budget)
  stay local; the repo carries `firebase-config.example.js` and
  `.firebaserc.example` with placeholders, and the build and the gate fall
  back to the example. Never write a project id, key, site name, service
  account or reCAPTCHA key into a tracked file: hosting uses targets (`game`,
  `redirect`), functions use `GCLOUD_PROJECT`/`FIREBASE_CONFIG`, short service
  account names (`stats-writer@`) and `SITES`. Scan before every push.
- **App Check (reCAPTCHA Enterprise) is ENFORCED** on the Realtime Database and
  on Identity Toolkit: any new Firebase product must activate App Check before
  use. The browser key is restricted by referrer and to four APIs; a new domain
  goes into the key and the reCAPTCHA key. A monthly budget with
  `billingGuard` (`functions/index.js`) unlinks billing when it's reached —
  don't add paid services without considering it.
- **Stats are anonymous by construction**: `js/stats.js` sends beacons of
  allowlisted values only (`functions/stats.js` validates them again and only
  increments totals); no ids, no cookies, no free text — a chapter name counts
  only if it starts with GDG/GDSC/WTM. A new event, language or source must be
  added to `functions/stats.js` too (the gate compares them). The game diary
  (`logs/d|q|x`: each day's summary, days left halfway, game errors) uses
  random keys and the date only, never a timestamp or id; `api` prunes it
  after 12 months. Request logs with IPs stay in Cloud Logging (30 days) by the
  user's choice, for troubleshooting.
- **The site is `overbooked.web.app`** (hosting target `game`); the target
  `redirect` sends the project's default site there. A new domain goes into
  the API key referrers, the reCAPTCHA key, Auth's authorized domains and
  `SITES` in `functions/.env.<project>`.
- **The Google account is optional**: never gate gameplay behind it.
  `js/account.js` syncs `ovb_progress/best/kit/mycards/chapter/city` through a
  `DF.storage.set` hook; `users/<uid>` is owner-only, `lb/u/<uid>` feeds the
  board (function `board`), `/api/board` serves it. The popup must open inside
  the click (prepare the SDK first). `googleSignIn` in `firebase-config.js`
  shows the button; COOP stays `same-origin-allow-popups`.
- **Orders and posts**: tapping the co-org (a bot) or a volunteer selects it
  (`DF.Render.R.select`), the next tap gives the job. Orders reach bots as
  commands with `order: true`; `js/bot.js` obeys `o.order` until it's done.
  Volunteers at a post with nothing to fix `serve` (sim event): small sat
  gains normalised by day length, shown as cups/answers by the renderer.
- **Rush hours** (`s.script.rush`, `updateRush` in `js/sim.js`) draw from
  their own RNG (`s.rushRng`) so adding them doesn't reshuffle the rest of
  the day; their problems cost half, winning gives a small bonus. Sold-out
  (`cfg.soldout`) scales spawns ×1.25 and attendees ×1.4 (main.js and
  playtest). The chat's consequences are texts `chat.fx.<tpl>` [good, other,
  ignored]: a new chat act needs them.
- **Venues** (`js/venue.js`): every venue keeps the same 22 stations and room
  ids (the station contract); `DF.Venue.use(id)` swaps the map in place and
  the sim calls it in `createDay`. Draw venue props relative to stations, never
  at fixed tiles; per-venue looks (stages, screens, labels) live in the data.
- **Weekly challenge** (`js/weekly.js`): the client records inputs per step,
  the `api` function replays them with copies of the pure modules in
  `functions/game/` (`node tools/build.mjs` refreshes them; the gate checks
  they match). Anything that changes the sim changes the replay: keep the
  gate's replay check green.
- **Role abilities** (`useAbility` in sim): one per role with a cooldown; bots
  use them with a probability (`profile.ability`) so the curve stays honest.
- **Phones**: `js/render.js` draws the venue through a camera (`R.zoom`,
  following the local organizers) and the HUD/bar at `R.ui` scale; picking and
  coach spots go through it (map spots are venue coordinates with
  `map: true`). `?mobile` forces the phone layout on a desktop. On phones the
  bar is taller and holds the venue map (`drawMiniMap`, `R.miniScr`): a tap
  there picks the nearest problem or that floor spot.
- **The GDG box**: a fixed dashed zone on the control room floor
  (`drawBoxZone`) marks where tools are picked up; the tools appear in the
  bar's left half (`drawBoxBar`, `R.trayScr`), never on the map.
- **Gestures**: TAP to go (tap a problem = go and fix it), HOLD to work by
  hand, keyboard for two players, Q/E to answer the staff chat. The tutorial
  and the pace (`ev.pace`, relaxed mode) exist so players have time to read.
- **Nothing covers the map while time runs**: messages go to the radio and
  chat bar below the venue. Only the coach card sits on the map, and the day is
  paused while it is open. Keep walls of text short.
- The preview pane throttles requestAnimationFrame and CSS animations when
  hidden: verify time-based behaviour with `?dev` hooks or Node.
- Sprites are generated offline (`tools/gen_sprites.py`, style reference in
  `tools/sprites_raw/_ref.png`), never at runtime; run `--webp` after
  regenerating, the build embeds the WebP copies.
- Bump `DF.VERSION` in `js/core.js` on every release.
